# 헤어스타일 추천 첫 흐름

`PRODUCT.md`의 핵심 루프를 처음부터 끝까지 한 번 돌려볼 수 있게 하는 첫 구현 범위입니다. 사진 입력, 추천 스타일 그리드, 터치로 돌려보는 360도 보기, 미용실 추천(근처/원거리 구분)을 다룹니다.

## 사용자에게 보이는 결과

1. 사용자는 자기 사진을 넣기 전에 "분석을 위해 사진이 외부 AI 서비스로 전송되고, 분석 후 저장되지 않는다"는 안내를 보고 동의 여부를 정한다.
2. 동의하고 사진을 넣으면, 사진과 어울릴 만한 스타일 후보가 사진 그리드로 여러 장 나온다.
3. 사용자가 후보 하나를 고르면 그 스타일을 앞, 오른쪽, 뒤, 왼쪽 네 방향으로 볼 수 있다. 화면을 좌우로 쓸거나 마우스로 끌면 방향이 돌아간다.
4. 고른 스타일을 해주는 미용실이 근처와 원거리로 나뉘어 나온다.
5. 사용자는 다른 후보로 돌아가 같은 과정을 반복할 수 있다.

## 승인된 범위

- **스타일 목록**: 앱에 내장한 스타일 목록을 쓴다. 스타일마다 네 방향 이미지와, 그 스타일을 해주는 미용실 정보가 연결되어 있다. 인터넷 검색은 이번 범위가 아니다.
- **이미지**: 임시(플레이스홀더) 이미지를 쓴다. 실제 사진은 라이선스를 확보한 뒤 같은 자리에 교체한다.
- **사진 분석**: Claude API(비전)로 사용자 사진을 분석해, 내장 스타일 목록 안에서 어울릴 만한 후보를 고른다.
- **미용실**: 내장한 가상의 미용실 목록을 쓴다. 실제 지도나 장소 검색 API는 쓰지 않는다.
- **근처 판단**: 사용자가 브라우저에서 위치 사용을 허락하면 그 위치를 기준으로 근처와 원거리를 나눈다.

## 수용 기준

### 동의와 프라이버시
- 사진을 선택하기 전에 외부 AI 서비스로 전송된다는 안내가 보이고, 동의 없이는 사진이 전송되지 않는다.
- 동의하지 않은 사용자에게는 분석 없이 내장 스타일 전체를 같은 그리드로 보여주고, 이후 흐름(360도 보기, 미용실 추천)은 그대로 쓸 수 있다.
- 분석이 끝난 사진은 서버나 브라우저에 남지 않는다. 이번 범위에는 사진 저장 기능이 없다.

### 추천 그리드
- 동의하고 분석이 성공하면 어울릴 만한 스타일을 여러 장(최소 4장) 그리드로 보여준다. 정답 하나만 보여주지 않는다.
- 분석 중에는 진행 상태가 보이고, 분석에 실패하면 실패 사실을 알린 뒤 내장 스타일 전체를 보여준다.
- 좁은 화면에서는 그리드 열 수가 줄어도 모든 후보에 접근할 수 있다.

### 360도 보기
- 스타일을 고르면 네 방향 이미지 중 앞모습에서 시작한다.
- 좌우로 쓸거나 끌면 방향이 순서대로 돌아가고, 끝에서 처음으로 이어진다.
- 터치가 없는 환경에서도 키보드 좌우 방향키로 같은 동작을 할 수 있다.

### 미용실 추천
- 고른 스타일을 해주는 미용실만 추천한다.
- 위치를 허락한 경우: 근처에 맞는 미용실이 있으면 근처 목록을 보여준다. 근처에 맞는 곳이 없으면 먼 곳의 맞는 미용실을 추천하고, 근처 미용실은 스타일과 무관하게 별도 목록으로 보여준다.
- 위치를 허락하지 않았거나 알 수 없는 경우: 근처 여부를 나누지 못한다는 점을 알리고, 맞는 미용실을 거리 구분 없이 보여준다.
- 각 미용실에는 이름과, 위치를 아는 경우 사용자로부터의 거리가 표시된다.

## 확정된 제약과 이유

- 첫 구현은 내장 스타일 목록과 임시 이미지를 쓴다. 인터넷 사진은 네 방향 세트를 안정적으로 얻기 어렵고, 외부 검색 키 없이도 핵심 루프를 끝까지 확인하기 위해서다.
- 사용자 사진 분석은 실제 AI로 하되 동의를 받는다. 얼굴 사진이 외부로 나가기 때문이며, 동의하지 않아도 앱의 나머지 흐름은 막히지 않아야 한다.
- 합성(사용자 얼굴에 스타일을 입힌 360도 보기)은 이번 범위에서 제외한다. 별도 이미지 생성 서비스와 키, 비용이 필요하고 옆과 뒤 모습의 품질 위험이 크기 때문이다.
- `PRODUCT.md`에서 가져오는 제약: 어울림은 주관적이므로 후보를 여러 개 제시하고 결정은 사용자가 한다. 얼굴 사진은 동의 없이 저장하지 않는다.
- UI는 `docs/decisions/ui-composition.md`를 따른다. 일반 UI는 shadcn/ui 구성으로 만들고, 360도 보기 표면만 필요하면 직접 구현할 수 있다.

## 가정 (덮어쓸 수 있음)

- 스타일 목록은 12개 안팎이고, 미용실 목록은 근처와 원거리가 모두 나올 만큼 여러 지역에 흩어진 가상 데이터다.
- "근처"는 사용자 위치에서 가까운 거리 안에 있는 곳이며, 구체적인 기준 거리는 구현에서 정해 화면에 드러낸다.
- 네 방향 이미지는 같은 스타일 안에서 같은 크기와 비율을 쓴다.
- Claude API 키는 환경 변수로 주입하며, 키가 없으면 분석 실패와 같은 방식(내장 스타일 전체 표시)으로 동작한다.
- 한 화면 흐름 안에서 단계가 이어지며, 계정과 로그인은 없다.

## 범위 밖

- 인터넷에서 스타일 사진을 검색해 오는 일: 이번에는 내장 목록으로 대체한다.
- 실제 미용실 검색과 지도: 가상 데이터로 대체한다.
- 사용자 사진 저장과 이전 결과 보관: 동의 기반 저장은 다음 단계다.
- 사용자 사진과 스타일 합성: 아래 미정 항목을 참고한다.
- 예약, 계정, 즐겨찾기, 공유.

## 미정 항목

- **합성 360도 보기**: 사용자 얼굴에 스타일을 입힌 360도 보기. 이미지 생성 서비스를 정한 뒤 결정한다. 그때까지 360도 보기는 스타일 자체의 임시 이미지를 보여준다(임시 동작). 합성이 정해지면 360도 보기의 이미지 자리를 합성 결과로 바꾼다.
- **실제 인터넷 사진과 실제 미용실**: 외부 검색 서비스를 정한 뒤 결정한다. 그때까지 내장 목록과 가상 미용실을 쓴다(임시 동작).
- **성공 신호 기준**: `PRODUCT.md`의 "자주 사용"을 측정하는 기준은 아직 없다.

## 남은 위험

- 임시 이미지로는 AI가 고른 후보가 실제로 어울리는지 눈으로 판단하기 어렵다. 추천 품질은 실제 사진을 넣은 뒤에야 평가할 수 있다.
- 가상 미용실 데이터로는 "근처/원거리" 구분이 실제 지역에서 쓸 만한지 검증되지 않는다.
- 외부 AI 호출은 응답 시간과 실패 가능성이 있어, 사용자가 기다리거나 폴백(전체 스타일 표시)을 보게 될 수 있다.
